# 横截面因子、排序损失与因子依赖约束技术方案

方案日期：2026-10-09。配套文件为[实验计划](横截面因子与排序损失实验计划.md)。本方案规定本机单模型训练的配置、程序接口、运行顺序和验收条件。因子组依赖约束属于输入敏感度约束，其结果不解释为因果效应。

## 1. 固定模型与程序职责

正式任务只有一个：使用随机种子 42，从随机初始化开始训练 37 通道 LSTM-Transformer。输入为原有 27 个因子与已验收的 10 个横截面因子；训练损失固定为 Smooth L1 收益损失、权重 0.3 的同日排序损失，以及权重 0.1 的因子组依赖超限惩罚。正式运行使用本机 RTX 4060 Laptop GPU。

| 文件 | 单模型职责 |
|---|---|
| `横截面因子与排序损失实验配置.json` | 保存唯一模型、随机种子、输入身份、损失、早停、评价和本机路径参数 |
| `cross_section_experiment.py` | 校验单模型配置、读取路径、核对已完成输入和文件摘要 |
| `cross_section_input.py` | 拼接真实 37 通道窗口，提供同日采样和按批推理 |
| `lstm_transformer_small.py` | 构建固定输入维度为 37 的模型 |
| `ranking_loss.py` | 计算收益损失与同日股票排序损失 |
| `dependence_constraint.py` | 确定七组来源、计算训练中性值、执行通道替换和超限惩罚 |
| `train_cross_section_rank.py` | 在本机连续训练一个模型、逐周期验证、早停与中断恢复 |
| `evaluate_cross_section_rank.py` | 检查预测质量、依赖程度、推理稳定性，选择周期并评价留出集与官方测试集 |
| `verify_cross_section_rank.py` | 核验真实输入、真实批次、检查点恢复、评分一致性和最终产物 |
| `finalize_cross_section_rank.py` | 生成单模型实验报告和产物摘要 |
| `coordinate_cross_section_rank.py` | 顺序执行本机预检、训练、模型选择、留出评价、测试预测及报告生成 |
| `audit_cross_section_delivery.py` | 将原始资格字段及原因写入缺失键文件，核对预测与缺失键完整覆盖官方测试集，更新最终产物摘要 |

训练入口直接执行单模型循环。程序只读取一个模型定义和 `seed=42`，模型目录使用唯一运行标识，并在配置快照中保存摘要，启动时核对检查点的运行身份。

| 排序损失权重、排序温度 | 0.3、0.02 |
| 依赖约束 | 启用；阈值 0.25、权重 0.1、分母下限 `1e-8` |

## 3. 输入接入与时间资格

启动时读取 `模型预处理/横截面扩展输入/20261008_横截面排序优化/数据交付清单.json`、`输入元数据.json` 和 `数据核验结果.json`。要求交付清单与元数据均为 `complete` 且 `data_verified=true`，核验结果为 `passed`。重新计算原有存储、新增存储、处理参数、交易日期表、股票元数据和四分区索引的 SHA-256，并与交付清单及配置核对。

原有特征存储形状为 `(9499950,27)`，新增特征存储形状为 `(9499950,10)`，均为 float32。对每条合格记录按同一股票的 20 个历史交易日读取两个存储，沿通道维度拼接成 `(B,20,37)`。窗口起点、目标行地址、股票身份、交易日期、特征列顺序和数值有限性必须通过核验。原有 27 通道逐元素保持与原读取器一致。

训练使用 4,510,263 条 `training_eligible=1` 记录，验证生成 1,055,569 条合格预测，再使用 1,051,065 条 `selection_eligible=1` 记录选择周期。训练排除 2022-12-30 的 4,273 条跨界标签，验证选择排除 2023-12-29 的 4,504 条跨界标签。标签实现日期按已验收交易日期表核对。2024 年留出集和官方测试集均不参与参数更新或周期选择。

## 4. 本机训练与损失计算

启动训练前检查 `.venv\Scripts\python.exe`、PyTorch CUDA、RTX 4060 Laptop GPU 显存，以及真实 512 条同日 37 通道批次的前向计算、反向计算和参数更新。`CUBLAS_WORKSPACE_CONFIG=:4096:8` 在首次 CUDA 初始化前设置；固定 Python、NumPy、PyTorch CPU/CUDA 随机状态，启用确定性算法并关闭 cuDNN 自动性能搜索。

`SameDateBatchSampler` 按随机种子 42、周期和交易日期生成顺序。每天的股票记录按最多 512 条均衡分批；一个周期覆盖全部 4,510,263 条训练记录恰好一次，固定数据对应 9,393 个批次。批次核对同日、股票代码唯一、输入身份和真实收益标签。

模型使用 64 维输入投影、一层隐藏维度 64 的 LSTM、一层四注意力头 Transformer、128 维前馈层和回归输出层，Dropout 为 0.1。AdamW 学习率为 0.0003、权重衰减为 0.0001，梯度范数裁剪上限为 1.0。

收益损失为 `smooth_l1_loss(pred,target,beta=0.02,reduction='mean')`。排序损失对同一交易日内 `i<j` 且真实收益不同的股票对等权计算：

```text
L_rank = mean[0.02 × softplus(−sign(y_i−y_j) × (p_i−p_j) / 0.02)]
```

没有有效股票对时返回保留计算图的零损失。所有预测、标签、损失、梯度和更新后的参数均须为有限数值。

## 5. 因子组依赖约束

因子来源按以下顺序编号 0—6：

| 编号 | 输入因子 |
|---:|---|
| 0 | `ret_1d`、`excess_ret_1d` |
| 1 | `mom_5d`、`csrank_mom_5d`、`excess_mom_5d` |
| 2 | `mom_20d`、`csrank_mom_20d` |
| 3 | `volatility_5d`、`csrank_volatility_5d` |
| 4 | `amount_shock_5d`、`csrank_amount_shock_5d` |
| 5 | `intraday_ret`、`csrank_intraday_ret` |
| 6 | `market_mean_ret_1d`、`market_breadth_1d`、`market_dispersion_1d` |

从全部 `training_eligible=1` 记录的目标时间步估计每个指定通道的中位数，保存数值与配置、输入摘要。每个训练批次使用 `group_index=(batch_id+42)%7` 选择一组，把该组在全部 20 个时间步的数值替换为训练中位数；每个周期重新从 `batch_id=0` 编号。原始输入预测为 `p`，替换输入预测为 `q_g`，使用相同模型参数和相同 Dropout 随机状态。

```text
R_g = std(p−q_g, ddof=0) / max(std(p, ddof=0), 1e−8)
L_total = L_return + 0.3 × L_rank + 0.1 × max(R_g−0.25, 0)²
```

模型对替换输入再执行一次前向计算，随后恢复原始前向之后的随机状态，使下一批次随机序列保持连续。保存每组抽取次数、平均依赖程度、超限比例和惩罚项。替换仅用于训练约束及验证核验，正式预测读取完整输入。

对候选检查点使用 241 个完整验证选择日期逐日计算七组 `R_g`。同一日期聚合全部合格股票后计算 float64 总体标准差，每组至少 229 个日期满足 `R_g≤0.25`。保存逐日期比值、通过数量、原始预测标准差和检查点摘要。检查结果只表明模型的输入敏感度。

## 6. 周期、检查点和模型选择

每 100 个优化步骤保存恢复检查点；每个完整周期保存模型、AdamW、随机状态、采样摘要、训练日志和验证预测。恢复时核对配置、输入、模型维度、周期及下一批次位置，恢复优化器张量和随机状态，从持久化的下一批次继续。已有完整周期检查点而验证未完成时，只补全该周期验证。

每个周期在完整验证预测上按股票时间顺序计算固定 `alpha=0.3` 的平滑分数，然后筛选 2023 年选择资格记录。比赛综合分为 `0.4×平均RankIC+0.3×Top10%年化超额收益+0.3×(1−平均换手率)`。早停监控该分数：改善严格超过 0.0001 时更新最佳值，否则增加停滞计数；第 6 周期及以后连续 3 个周期未改善时停止，第 12 周期为上限。数值质量无效周期计为一次未改善。

训练结束后按综合分从高到低检查候选周期。分数容差为 `1e-8`，并列时依次使用 Rank IC、年化超额收益、较早周期。每个待选周期执行每日原始预测质量检查、七组因子依赖程度核验和双批量排序稳定性检查。原始预测出现常数日期即失去选择资格；预测跨度在至少 95% 的选择日期内不超过输出量级的 32 个 float32 相邻数间距时也失去资格。预测标准差与标签标准差之比低于 `1e-4` 或并列比例超过 95% 时记录预警。

双批量核验分别用 4096 和 2048 条记录推理，在同一股票日期键上比较。至少 99% 的选择日期须同时满足原始预测 Spearman 相关系数不低于 0.99，以及固定平滑分数对应的收益与换手率 Top10% 选股集合重合比例均不低于 95%。第一个通过全部检查的周期写入只读选择记录。全部周期失去资格时生成失败报告，停止留出集与测试集推理。

## 7. 评分、留出集与官方测试集

每日 Rank IC 使用有效标签并保留涨停股票，至少 30 条记录；Top10% 收益排除涨停和缺失标签，至少 100 条记录，年化超额收益采用日均值乘 252；换手率排除涨停并保留标签缺失记录，至少 100 条记录，计算相邻持仓集合的 `1−交集数量/并集数量`。股票日期键、并列排序行为和各指标有效日期按比赛 `evaluate.py` 核验。本地评分程序在真实样本上与官方程序逐项比较，评分容差为 `rtol=1e-10, atol=1e-12`。

锁定选择记录后，对 2024 年本地留出集生成一次原始预测和一次 `alpha=0.3` 平滑预测，输出逐日指标、全年指标、七组因子依赖程度和预测质量。报告列出样本数量、有效日期、Rank IC、ICIR、Top10% 收益、换手率及综合分；本地留出结果不回写模型选择。

官方测试集只对 1,597,202 条合格窗口生成预测，输出股票日期键、预测值及覆盖审计。另有 2,398 条记录缺少合格序列，保存缺失键与资格原因。输出 `complete_submission=false`；只有全部 1,599,600 条测试键具备符合比赛要求的预测时，才生成正式提交文件。

## 8. 执行接口与产物验收

完整执行入口为 `coordinate_cross_section_rank.py --config CONFIG --run-dir RUN`，恢复已经通过预检的同一次运行时增加 `--resume`。执行状态写入 `执行状态.json`，每 100 批更新 `训练进度.json`，报告保存为 `模型结果评估报告.md`。各环节也可使用下列接口，读取同一配置与运行目录：

在项目根目录使用 PowerShell 执行：

```powershell
& '.venv/Scripts/python.exe' -X utf8 -u '模型训练/coordinate_cross_section_rank.py' --config '模型训练/横截面因子与排序损失实验配置.json' --run-dir '模型训练/横截面因子与排序损失实验/20261009_local_single'
```

本次运行记录目录为 `模型训练/横截面因子与排序损失实验/20261009_local_single`；终端日志保存于 `模型训练/横截面因子与排序损失实验/运行日志/20261009_local_single`。同一运行只允许一个活动进程。恢复前先确认原进程已结束，在完整执行命令末尾增加 `--resume`。

| 顺序 | 命令接口 | 完成条件 |
|---:|---|---|
| 1 | `verify_cross_section_rank.py --config CONFIG --run-dir RUN --operation preflight --device cuda` | 输入、真实批次、梯度、恢复及官方评分核验通过 |
| 2 | `train_cross_section_rank.py --config CONFIG --run-dir RUN --device cuda` | 单个随机种子完成早停或第 12 周期；中断恢复使用 `--resume` |
| 3 | `evaluate_cross_section_rank.py --config CONFIG --run-dir RUN --operation select --device cuda` | 唯一检查点通过质量、依赖程度和双批量核验 |
| 4 | `evaluate_cross_section_rank.py --config CONFIG --run-dir RUN --operation holdout --device cuda` | 2024 年预测与指标完整 |
| 5 | `evaluate_cross_section_rank.py --config CONFIG --run-dir RUN --operation competition-test --device cuda` | 合格测试预测与缺失键审计完整 |
| 6 | `finalize_cross_section_rank.py --config CONFIG --run-dir RUN` | 单模型报告、文件摘要和最终核验通过 |
| 7 | `audit_cross_section_delivery.py --config CONFIG --run-dir RUN` | 缺失键包含原始资格字段与原因，预测键和缺失键合并后完整覆盖官方测试集 |

完整训练入口生成报告后，执行交付核验入口 `audit_cross_section_delivery.py`。交付核验使用已保存的固定模型预测与已验收索引，记录资格原因，并重新生成最终文件摘要。

最终核验要求一个训练运行具有完整周期检查点与验证记录，训练周期覆盖 4,510,263 条合格记录，模型选择检查全部通过，2024 年评估身份完整，官方测试合格预测为 1,597,202 条且缺失键为 2,398 条。报告记录实际每周期训练与验证耗时、显卡峰值显存、数值质量、七组依赖程度和测试覆盖状态。全部核验使用真实数据与真实模型输出。
