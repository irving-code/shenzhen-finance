# 排序信号优化技术方案

## 1. 技术目标

在现有 37 因子、20 日输入序列和 LSTM-Transformer 模型基础上，比较排序损失权重与时间平滑参数，使用 2023 年数据确定候选模型、训练周期和 alpha，再使用 2024 年完成一次历史留出评价。

本方案保持现有预处理结果和时间划分，不处理 2025—2026 年测试集 X，不读取测试集 Y，不生成 `submission.csv`。

## 2. 固定数据接口

继续读取现有横截面扩展输入目录：

```text
模型预处理/横截面扩展输入/20261008_横截面排序优化/
```

使用现有四个数据分区：

| 数据分区 | 时间 | 用途 |
|---|---|---|
| `train_fit` | 2018—2022 | 模型参数训练 |
| `validation` | 2023 | 候选模型、训练周期和 alpha 选择 |
| `local_holdout` | 2024 | 最终历史留出评价 |
| `competition_test` | 2025—2026 | 本方案不处理 |

所有候选使用相同的输入元数据、特征存储、样本索引、日期边界和随机种子。

## 3. 候选配置接口

新建独立实验配置，候选字段至少包含：

```json
{
  "feature_mode": "extended37",
  "rank_weights": [0.0, 0.15, 0.3, 0.5],
  "alphas": [1.0, 0.7, 0.5, 0.3],
  "seed": 42,
  "dependence_training_penalty": 0.0,
  "training": {
    "batch_size": 512,
    "inference_batch_size": 4096,
    "learning_rate": 0.0003,
    "weight_decay": 0.0001,
    "gradient_clip": 1.0
  },
  "ranking": {
    "beta": 0.02,
    "tau": 0.02
  }
}
```

每个候选的身份由以下字段共同确定：

```text
feature_mode + rank_weight + seed + data_hash + source_hash
```

每个候选保存独立的配置快照，记录输入摘要和程序摘要。已有两组实验配置继续保持只读。

## 4. 训练程序组织

新实验使用独立调度入口，复用现有训练模块中的以下能力：

- `SameDateBatchSampler` 同日训练批次；
- `compute_joint_loss` 收益损失与排序损失；
- `LSTMTransformerRegressor` 当前模型结构；
- 检查点保存和恢复；
- 训练周期状态记录；
- 预测质量与双批量推理稳定性检查。

候选 C 的排序权重为 0.3，可以复用已有无依赖惩罚实验检查点。候选 A、B、D 在新的候选目录中独立训练。所有候选均关闭训练阶段的因子依赖惩罚，依赖程度只在选定候选后进行诊断。

训练批次、输入顺序、随机种子和模型初始化规则保持一致，保证排序权重是主要变量。

## 5. 预测与 alpha 平滑

每个检查点在 2023 年生成原始预测表，字段为：

```text
ts_code
trade_date
pred
prediction_eligible
```

使用现有 `smooth_predictions` 逻辑进行股票级时间平滑：

```text
s_t = alpha × p_t + (1 - alpha) × s_(t-1)
```

同一股票按照交易日期排序，第一条记录使用当天原始预测。每个 alpha 生成独立的平滑预测表，保留原始预测表供 Rank IC 和收益变化分析。

## 6. 主办方评分适配

为每个候选、周期和 alpha 建立独立评分目录：

```text
validation_2023/
└── lambda_0.3/
    └── epoch_02/
        └── alpha_0.3/
            ├── 测试集_Y.csv
            ├── 测试集_X.csv
            └── 候选预测.csv
```

文件构造规则：

- `测试集_Y.csv` 从 2023 年现有验证索引读取 `ts_code`、`trade_date`、`y_ret_1d`；
- `测试集_X.csv` 从相同验证索引读取 `ts_code`、`trade_date`、`flag_limit_up`；
- `候选预测.csv` 使用相同股票日期键和当前候选的 `pred`；
- 三个文件都执行重复键、行数、键集合和数值有限性检查。

调用主办方原版 `赛题五/evaluate.py`：

```python
evaluate("候选预测.csv", "当前评分目录")
```

评分文件使用 `候选预测.csv` 名称，避免生成 `submission.csv`。所有候选的综合分均由同一个官方评分程序计算。

## 7. 候选选择记录

每个候选周期和 alpha 保存一条结构化记录：

```text
candidate_id
rank_weight
epoch
alpha
ic_mean
annual_excess
mean_turnover
final_score
quality_pass
stability_pass
```

候选选择顺序为：

1. 综合分降序；
2. Rank IC 均值降序；
3. Top10% 年化超额收益降序；
4. 训练周期升序；
5. alpha 降序。

同时要求候选通过：

- 非有限值检查；
- 常数预测检查；
- 预测质量检查；
- 4096 和 2048 推理批量稳定性检查。

## 8. 2024 年历史留出评价

2023 年选择完成后，固定以下四项：

```text
candidate_id
rank_weight
epoch
alpha
```

使用固定模型在 2024 年生成原始预测和平滑预测，计算：

- Rank IC 均值、标准差、ICIR 和正 IC 比例；
- Top10% 年化超额收益和 Top10% 年化绝对收益；
- 平均换手率和 `1 - 平均换手率`；
- 综合分；
- 月度指标；
- 与当前已知实验结果的差异。

2024 年结果只作为历史留出核验，不回写候选选择记录，不修改 2023 年选择结果。

## 9. 核验要求

每个候选至少完成以下核验：

- 配置摘要与运行目录一致；
- 输入摘要与现有预处理产物一致；
- 训练记录覆盖全部合格训练样本；
- 训练批次数量符合当前采样器记录；
- 检查点可以恢复；
- 预测股票日期键无重复、无缺失；
- 预测值均为有限数值；
- 2023 年每天具有足够的有效标签；
- 原始预测和 alpha 平滑预测均通过数值质量检查；
- 4096 与 2048 推理批量的排序结果满足现有稳定性要求；
- 本地评价结果与主办方 `evaluate.py` 的指标一致。

## 10. 目录和文件

新实验使用独立目录：

```text
模型训练/

    └── 20261009_rank_weight_alpha/

        ├── 候选配置/

        ├── comparison/
```

临时评分目录放在项目目录内的专用临时目录，并加入 `.gitignore`。已有实验目录、检查点、报告、配置和预处理产物不被覆盖。

## 11. GPU 资源控制

使用 RTX 4060 Laptop GPU 单任务运行，保持训练批量 512 和推理批量 4096。关闭依赖惩罚后，单周期训练时间参考现有约 12.5 分钟，验证推理约 0.3—0.4 分钟。

候选任务按顺序运行，候选 C 优先复用已有检查点。训练过程保留周期级检查点和恢复记录，避免重复执行已经完成的候选周期。

## 12. 交付边界

本技术方案完成后，交付候选比较表、2023 年官方评分记录、最终候选的 2024 年历史留出结果和实验报告。

本方案不生成测试集 X 预测，不读取测试集 Y，不生成正式 `submission.csv`。
