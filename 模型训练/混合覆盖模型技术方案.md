# 混合覆盖模型技术方案

## 1. 技术目标

建立一条可以复用的完整测试集预测流程：严格排序模型处理完整历史序列记录，LightGBM 处理序列输入不足记录，最终按测试集原始键表生成一行一预测的提交文件。

技术方案保留现有数据预处理和模型权重，新增覆盖标记、预测校准、键表合并和最终审计功能。

## 2. 输入和输出

### 2.1 输入

- 测试集 X 因子文件；
- 现有标准化和特征处理结果；
- 严格排序模型最佳权重；
- LightGBM 已训练模型；
- 2024 年本地留出集预测，用于校准和评价；
- 测试集完整键表 `(ts_code, trade_date)`。

### 2.2 输出

- `submission_hybrid.csv`：包含 `ts_code`、`trade_date`、`pred` 三列；
- `混合模型覆盖审计.json`：记录总行数、覆盖行数、缺失行数和重复键数量；
- `混合模型校准参数.json`：记录每个交易日的校准参数和全局备用参数；
- `混合模型留出集评估.csv`：记录各模型的评价指标；
- `混合模型实验报告.md`：记录完整实验结论。

## 3. 数据处理流程

### 3.1 建立完整测试键表

从测试集 X 读取全部 `(ts_code, trade_date)`，保留原始顺序并生成唯一键：

```python
test_keys = test_x[["ts_code", "trade_date"]].drop_duplicates()
```

执行以下检查：

```text
test_keys 行数 = 测试集 X 行数
test_keys 唯一键数量 = test_keys 行数
ts_code 和 trade_date 均无空值
```

这张键表是最终提交文件的主表，任何模型预测都必须左连接回这张表。

### 3.2 执行现有预处理

继续使用项目已有处理顺序：

1. 读取原始因子；
2. 对已有记录中的因子缺失值执行填充；
3. 执行异常值处理；
4. 使用训练集参数完成标准化；
5. 保留 `ts_code`、`trade_date` 和行索引；
6. 将处理后的因子与完整键表关联。

字段填充只处理已有记录中的字段缺失。历史交易行缺失和历史窗口不足由后续 `eligible_mask` 处理。

### 3.3 生成严格排序模型输入

序列构造函数必须同时返回序列数据和键映射：

```text
X_sequence
sequence_keys
eligible_mask
```

其中：

- `X_sequence` 是严格排序模型需要的固定长度序列；
- `sequence_keys` 是每个序列最后一个交易日对应的股票—日期键；
- `eligible_mask` 标记完整键表中能够生成序列的位置。

序列构造阶段不得丢失键映射。所有严格排序预测结果都必须带有 `ts_code` 和 `trade_date`。

## 4. 两个模型的推理流程

### 4.1 严格排序模型

使用现有最佳权重加载模型，输入 `X_sequence`，得到：

```text
strict_pred(ts_code, trade_date)
```

推理后检查预测行数是否等于 `sequence_keys` 行数，并检查预测值是否存在空值或无穷值。

### 4.2 LightGBM

使用现有 LightGBM 模型对完整测试集逐行推理，得到：

```text
lgbm_pred(ts_code, trade_date)
```

LightGBM 预测必须覆盖完整键表。若出现缺失键，应在生成混合结果前直接终止并写入错误位置。

## 5. 预测校准实现

在 2024 年本地留出集上建立两种模型的重叠预测表：

```text
overlap = strict_pred.join(lgbm_pred, on=["ts_code", "trade_date"])
```

按 `trade_date` 计算校准参数：

```text
lgbm_mean
lgbm_std
strict_mean
strict_std
overlap_count
```

对 LightGBM 兜底预测执行：

```python
z_lgbm = (lgbm_pred - lgbm_mean) / lgbm_std
calibrated_lgbm_pred = strict_mean + strict_std * z_lgbm
```

建议使用以下参数有效性条件：

```text
overlap_count >= 30
lgbm_std > 1e-8
strict_std > 1e-8
```

不满足条件时使用全局参数。全局参数同样只从 2024 年留出集重叠样本计算。

校准后保留以下字段，便于审计：

```text
ts_code
trade_date
lgbm_pred_raw
lgbm_pred_calibrated
calibration_scope
```

## 6. 预测合并实现

将严格排序预测、校准后的 LightGBM 预测和完整测试键表分别左连接到主表。最终合并逻辑为：

```python
result["pred"] = result["strict_pred"]
missing_strict = result["pred"].isna()
result.loc[missing_strict, "pred"] = result.loc[missing_strict, "lgbm_pred_calibrated"]
```

同时生成来源字段：

```text
prediction_source = strict_sort
prediction_source = lgbm_fallback
```

来源字段写入审计文件，提交文件本身只保留规定的三列：

```text
ts_code, trade_date, pred
```

## 7. 覆盖审计

最终文件生成前执行：

```text
total_test_rows
strict_prediction_rows
lgbm_prediction_rows
strict_coverage_rate
final_rows
unique_key_rows
duplicate_key_rows
null_prediction_rows
infinite_prediction_rows
```

必须满足：

```text
final_rows == total_test_rows
unique_key_rows == total_test_rows
duplicate_key_rows == 0
null_prediction_rows == 0
infinite_prediction_rows == 0
```

按交易日统计预测数量，并与测试集键表逐日比较。任意交易日数量不一致时，停止生成正式提交文件。

## 8. 留出集评价实现

在 2024 年本地留出集上完整运行相同的合并流程，得到三类结果：

- 严格排序模型有效序列样本结果；
- LightGBM 全量样本结果；
- 混合模型全量样本结果。

评价代码统一计算：

```text
rank_ic
icir
positive_rank_ic_ratio
annual_excess
annual_top_decile_return
mean_turnover
rank_ic_contribution
annual_excess_contribution
turnover_contribution
final_score
```

综合分实现为：

```python
final_score = (
    0.4 * rank_ic
    + 0.3 * annual_excess
    + 0.3 * (1.0 - mean_turnover)
)
```

## 9. 文件和脚本组织

建议新增以下脚本：

```text
模型训练/评估混合覆盖方案.py
模型训练/构建混合提交.py
```

`评估混合覆盖方案.py` 负责：

- 读取 2024 年留出集预测；
- 建立重叠样本；
- 计算交易日级和全局校准参数；
- 生成三种模型的指标；
- 输出混合模型评估表和实验报告。

`构建混合提交.py` 负责：

- 读取测试集完整键表；
- 加载两个已有模型；
- 生成严格排序预测和 LightGBM 预测；
- 执行校准与合并；
- 执行覆盖审计；
- 生成 `submission_hybrid.csv`。

## 10. 运行顺序

```text
1. 执行评估混合覆盖方案.py
2. 检查混合模型留出集评估.csv
3. 检查混合模型校准参数.json
4. 执行构建混合提交.py
5. 检查混合模型覆盖审计.json
6. 读取 submission_hybrid.csv 并执行独立键检查
7. 将满足完整覆盖条件且 2024 年综合分最高的模型确定为正式提交模型
```

## 11. 复现要求

每次运行必须记录：

- 输入文件路径和文件哈希；
- 模型权重路径和文件哈希；
- 预处理参数路径；
- 运行时间；
- Python 和主要依赖版本；
- 随机种子；
- 严格排序预测行数；
- LightGBM 预测行数；
- 最终提交行数；
- 覆盖审计结果。

实验报告必须同时保存原始预测、校准预测和最终合并预测的统计信息，保证后续可以定位覆盖缺失、尺度变化和预测合并问题。
